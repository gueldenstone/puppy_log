# Gesundheit: vaccinations, preventive care and vet appointments — design

Status: reviewed, awaiting approval · 2026-11-13

## Intent

The household wants to know **whether the puppy's vaccination plan and the recommended
deworming / flea and tick treatments actually happened**, and not to forget vet appointments.
The plan comes from the vet, the breeder or the vaccination passport (Impfpass); the household
**enters it manually** (no built-in template). Separately there are ordinary vet appointments.
They also want the resulting dates **in their phone calendars** via a calendar subscription.

## Goals

- Enter planned care items (due dates) and vet appointments; tick care items off with the date
  they were done; see what is open, due soon, overdue and done.
- Optional repetition ("alle N Wochen"); completing a repeating item creates the next one.
- Reminders come from the **calendar subscription** (alarms in the feed), not from push: N days
  before (household default, overridable per entry), for appointments also 2 hours before.
- „Gesundheit“ tab: next appointment card, weight curve (exists), list „Impfungen und Vorsorge“.
- A subscribable iCalendar feed per person that always contains **all** household entries,
  including appointments the other person goes to.

## Non-goals

- Built-in vaccination/deworming templates or medical advice (user decision: manual plan).
- Medication schedules, symptoms diary, documents/photos of the Impfpass, costs.
- PDF/CSV export (separate later step).
- Writing back from the calendar (the feed is read-only).

## Anti-goals

- A calendar that misses entries (e.g. only "my" appointments) — the feed is household-wide.
- A calendar URL that leaks access to the app (the feed exposes only health entries and can be
  revoked).
- History that changes silently: done entries keep their recorded date even if a repeating
  series is edited later.

## Constraints

- Existing stack and conventions (see AGENTS.md, docs/design/DESIGN.md): Phoenix LiveView, Ash
  with AshSqlite, household-wide policies (`actor_present()`), code interfaces, PubSub notifiers,
  Cinder for Ash resource lists, `PuppyLogWeb.UI` components, Europe/Berlin via `PuppyLog.Clock`,
  every record stores its creator, UI German / code English, English URLs.
- No push notifications for health entries (user decision 2026-11-13); reminders are `VALARM`s
  in the iCalendar feed. iOS Calendar strips alarms from subscribed calendars unless „Alarme
  entfernen“ is switched off when subscribing — the settings UI must say so next to the URL.
- The dev server is reachable only inside the tailnet; a subscribed calendar refreshes only while
  the phone's Tailscale is connected (production will be public HTTPS later).

## Approaches

1. **One resource `HealthEntry` with a `kind`** (vaccination, deworming, flea_tick, other_care,
   vet_visit) — one list, one reminder path, one calendar feed; appointment-only fields
   (time, location, assignee) are simply nil for care items. **Chosen** (my call, user handed
   over the how).
2. Two resources (care plan item, vet appointment) — cleaner field sets, but list, reminders,
   calendar and later statistics would be built twice.
3. Model health as routines/occurrences — rejected: routines are weekday/time based, care items
   are single dates with repetition counted from completion.

iCalendar output is generated by a small in-app module (RFC 5545 subset: VCALENDAR, VEVENT,
VALARM, all-day and timed events, escaping, line folding) — no new dependency.

## Decided with the user

- Manual plan entry, no template. Two kinds of entries: preventive care (Impfung, Entwurmung,
  Floh/Zecke, andere Vorsorge) with „fällig am“, and vet appointments („Tierarzttermin“) with
  date, time, place and an optional assignee (who goes).
- Completing records the date it happened (default today) and who entered it; vaccinations may
  record vaccine / batch (Impfstoff/Charge) as optional text.
- Things that happened before the arrival (e.g. the breeder's first vaccination) can be entered
  directly as done with a past date.
- States: open, due soon (within the reminder lead time), due today, overdue (red), done.
- Optional repetition „alle N Wochen“; completing creates the next entry, counted **from the
  completion date**.
- **No push reminders** for health entries; reminders are alarms in the calendar subscription
  (user decision, replaces the earlier push plan): N days before (default from settings, e.g. 2)
  — care items at 09:00 local on that day; vet appointments at the appointment time N days before
  **and** 2 hours before.
- The calendar feed always contains **all** household entries, whoever is assigned.
- „Gesundheit“ page: card „Nächster Termin“, weight curve (existing), list „Impfungen und
  Vorsorge“ — open entries by due date, done ones below, with status chips.
- Calendar subscription: care items as all-day events on the due date, vet appointments with
  time and place; done entries stay in the feed with „✓“ in the title and without alarms. Each
  person has their own secret feed URL (same household content for everybody) in „Haushalt & Mitteilungen“, which can be regenerated (old URL stops
  working).

## My calls (builder may revise with care)

- Household default lead time lives in `PuppyLog.Daily.Settings` as `health_reminder_days`
  (default 2, 0–14); each entry stores its own `remind_days_before` copied from the default and
  editable („Erinnern: N Tage vorher“; 0 = on the day). Vet appointments additionally get the
  fixed 2-hour alarm.
- Alarms: care items (all-day, start 00:00 local) `TRIGGER;RELATED=START` at 09:00 N days before
  (e.g. N=2 → `-P1DT15H`; N=0 → `PT9H`); appointments `-PND` and `-PT2H`. `ACTION:DISPLAY` with the
  entry title as description. Done entries carry no alarms.
- „Due soon“ = within the entry's lead time; „überfällig“ = care item open after its due date,
  or a vet appointment whose date/time has passed while still open.
- Vet appointments can be marked „erledigt“ (the visit happened) or deleted; they have no
  repetition. Only care items repeat.
- Completing a repeating item: the next entry copies kind, title, notes and repetition, gets
  `due_on = done_on + N weeks`, and is linked to its predecessor (`previous_id`) for traceability.
  Editing the repeat interval affects only the open entry and future ones.
- Reopening a done entry is allowed (mistake); if it had created a successor that is still open
  and untouched, the successor is removed; otherwise the successor stays.
- Overdue care items get no extra reminder; they are red in the list and in the „Nächster
  Termin“ card.
- Calendar feed: `GET /calendar/:token.ics`, token = 32 random bytes URL-safe, stored hashed on
  the user (`calendar_token_hash`), shown once-copyable as a `webcal://` link and a plain https
  link with a copy button; „Neue Adresse erzeugen“ rotates it. Feed contains all entries from
  one year back up to the future, `REFRESH-INTERVAL`/`X-PUBLISHED-TTL` 1 hour, stable UIDs
  (`<entry id>@puppy-log`), times in Europe/Berlin with a `VTIMEZONE` or as UTC. No auth other
  than the token; unknown token → 404.
- Entry form follows `docs/design/entwuerfe/09-termin.html`: kind tiles (Impfung, Entwurmung,
  Floh/Zecke, Tierarzt, Anderes), Bezeichnung, Datum, Uhrzeit (appointments only), Ort and
  Zuständig (appointments only), Erinnern N Tage vorher (stepper), Wiederholen + Alle N Wochen
  (care only), Impfstoff/Charge (vaccinations, also editable when completing), Notiz.
- Routes: `/health` (tab), `/health/new`, `/health/:id` (edit sheet or page), completion via a
  sheet with date and optional batch.
- Health entries publish PubSub `health_entries:changed`; the tab and settings update live.

## Answers to the builder check (my calls)

- **Ownership:** `HealthEntry` lives in the existing `PuppyLog.Puppy` domain (next to profile and
  weight). `health_reminder_days` is added to `PuppyLog.Daily.Settings` (extend its `:save`
  action and the settings card). No push/reminder process changes (no push for health).
- **Repetition:** an empty interval means "no repetition" (that is how a series ends; deleting
  the open entry also ends it). Completing — including creating an entry directly as done — with
  an interval creates the successor at `done_on + N weeks`, even if that date is already past
  (then it shows as overdue, which is correct information). The successor copies
  `remind_days_before`, kind, title, notes, interval and batch is left empty.
- **Calendar token:** stored as a plain random token (not hashed) on the user via a dedicated
  update action outside the authentication flows, so the settings page can always show and copy
  it; anyone with database access could read everything anyway. „Neue Adresse erzeugen“ rotates
  it. The route uses its own pipeline without session/CSRF; unknown token → 404; no rate limiting
  (tailnet / household scale). Every member gets a feed regardless of `receives_reminders`.
- **Feed contents:** all household entries for every member; vet appointments get a default
  duration of 60 minutes; alarms as above (open entries only); the assignee and the place go into
  the event (location, and „Geht hin: <name>“ in the description). Deleted or reopened entries
  simply change/disappear on the next refresh.
- **Subscription help:** next to the URL the settings show a short German hint: on the iPhone
  „Einstellungen → Kalender → Accounts → Account hinzufügen → Andere → Kalenderabo hinzufügen“,
  paste the URL, and **switch off „Alarme entfernen“** so the reminders work.
- **„Nächster Termin“ card:** the earliest open entry across both kinds, overdue ones first
  (red, „seit N Tagen überfällig“); if nothing is open, „Keine offenen Termine“ with a link to add
  one.
- **Past open appointments** stay overdue (red) until someone marks them done or deletes them;
  no automatic cleanup.
- **Assignee:** optional `belongs_to :assignee, User` (household member), like routines.
- **UI pattern:** form as its own page (`/health/new`, `/health/:id`) like the routine editor;
  completion as a bottom sheet on the health tab (`/health/:id/done`) with date (default today)
  and, for vaccinations, Impfstoff/Charge. All household members may create, edit, complete and
  delete (`actor_present()`).

## Left to the builder

- Exact iCalendar formatting choices within RFC 5545, as long as Apple Calendar and Google
  Calendar import it including alarms (test with a fixture).
- Visual details within the existing design system.
